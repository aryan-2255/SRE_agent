The system NightShift watches and repairs

Astronomy Shop, container by container

An online telescope shop made of 31 Docker containers. Each box below is one container, built from its own folder under src/. They all run on one machine (your laptop now, the AWS VM later) and talk over one Docker network. Start everything with ./shop.sh start.

How NightShift finds and fixes problems here

  1. Find: error rate and latency in Prometheus cross a threshold.
  2. Explain: the error lines in OpenSearch and the failing trace in Jaeger point to one container.
  3. Blame: GitHub shows which commit changed that container’s src/ folder.
  4. Prove: the sandbox clones this repo and reproduces the bug with a test.
  5. Fix: rebuild only that one container, or roll it back to its last good image.
  6. Check: Prometheus shows the error rate back to normal.

Why this works for any system

NightShift doesn’t depend on this shop. It needs three things, and every system has them:

  • Signals: somewhere with logs, metrics and traces. Here that’s OpenSearch, Prometheus and Jaeger. Elsewhere it could be Datadog, CloudWatch or Grafana Cloud.
  • Controls: a way to deploy and roll back. Here that’s Docker Compose. Elsewhere it could be Vercel, Render or AWS.
  • Code: a GitHub repo, like this fork.

Only the adapters inside nightshift-ops change. The agents stay the same.
